# 2026-05-16: 오늘 일기가 없을 때 어느 날짜에 추가할지 물어보기

## 배경

기존 webhook은 사용자가 텍스트 메시지를 보냈는데 오늘 날짜 일기 페이지가
Notion에 아직 없으면 `"{date} 일기를 아직 찾지 못했어요..."` 만 답하고 끝났다.
봇이 오후 8시 요약을 보내기 전, 또는 GitHub Actions가 어떤 이유로 실패한
날엔 사용자가 보낸 코멘트가 그대로 유실됐다.

사용자 요청: "오늘 일기가 없으면 어느 날짜에 추가할지 물어보고, 답변에 따라
그 날짜 일기에 넣어줘."

## 변경

### `api/webhook.py`

- 상수 추가
  - `PENDING_DATE_MARKER = "[haru-bot:pending-date]"` — prompt 식별용 prefix
  - `MSG_DELIMITER = "\n──[메시지]──\n"` — prompt 본문에서 원본 사용자 메시지를
    분리하는 구분선
  - `DATE_PARSE_MAX_TOKENS = 80`

- `_parse_date_answer(text, today)` 신규
  - 사용자가 답장한 짧은 한국어("어제", "그제", "2026-05-14", "5월 14일" 등)를
    Claude API로 `YYYY-MM-DD`로 변환
  - JSON 한 줄로만 답하라고 system prompt 지정, ` ```json ` fence 방어
  - 해석 실패 시 None
  - 키워드 dict 대신 LLM 위임 — `feedback_llm_over_keyword_rules` 메모리 규칙 준수

- `_send_pending_date_prompt(chat_id, today, user_text)` 신규
  - `force_reply: True` 메시지로 사용자에게 날짜를 묻기
  - **state-less 설계**: 사용자 원본 메시지를 prompt 본문 끝(MSG_DELIMITER 뒤)에
    그대로 박아 둔다. 사용자가 답장하면 Telegram이 reply_to_message 필드에
    이 prompt를 통째로 실어 주므로 Notion 등 외부 저장소 없이 원본 복원 가능.

- `_extract_pending_text(reply_to)` 신규
  - `reply_to_message`가 봇이 보낸 메시지이고 PENDING_DATE_MARKER로 시작하고
    MSG_DELIMITER가 포함돼 있으면 그 뒤를 원본으로 반환. 아니면 None.

- `_handle_date_answer(message, original_text)` 신규
  - 사용자의 답장 텍스트를 Claude로 날짜 파싱
  - 그 날짜 일기 페이지를 search로 찾아 `_process_user_input`으로 discussion에
    누적 + Claude 응답 생성
  - 페이지가 없는 날짜면 거절 (사용자 요청: "기존 페이지에만 추가")
  - 파싱 실패면 재요청 메시지

- `_handle_text_message` 수정
  - 함수 진입 직후 `_extract_pending_text` 검사 → 우리 prompt 답장이면
    `_handle_date_answer`로 라우팅하고 종료
  - 오늘 일기 페이지 없을 때 분기를 단순 거절에서
    `_send_pending_date_prompt`로 교체

## 사용자 흐름

1. 사용자: "오늘 너무 피곤했어"
2. 봇: pending-date prompt + force_reply (원본 메시지 embed)
3. 사용자: "어제" (Telegram이 자동으로 reply_to_message 설정)
4. 봇: Claude로 "어제" → `2026-05-15` 파싱 → 그 날짜 페이지 찾기 →
   `_process_user_input`(원본 텍스트) → discussion에 `• 나: ...` 추가 + Claude reply

## 미적용 / 차후 검토

- 사진/영상은 동일한 흐름을 적용하지 않음. 첨부 파일은 prompt 본문에 박을 수
  없어 force_reply 만으로는 state-less 복원이 안 됨. 필요해지면 Notion에
  pending 슬롯을 만들어야 한다.
- 답장이 아닌 일반 텍스트로 두 번째 메시지를 보내면 각각 별도 pending prompt가
  생성된다 (의도적). 사용자가 그 중 하나에만 답장하면 됨.
