# 2026-07-05 "한 일" 판정을 사용자 체크 기반으로 전환 + 애매한 캘린더 항목 질문 흐름

## 배경 (2026-07-04 만두 사건)

7/4 저녁 일기에 "오전에 만두 빚고 …"라고 기록됐지만 사용자는 만두를 빚은 적이 없음.
"만두"는 캘린더에 적어둔 **냉동실에 만두 있다는 메모**였는데:

1. `calendar.py`가 "종료 시각이 지난 일정 = done=true"로 추정 (종일 일정은 무조건 완료)
2. `notion.py`가 할일 DB 소속이 아닌 페이지(그날 편집한 아무 페이지)를 전부 done=true 처리
3. `summarizer._build_user_prompt`가 이 가짜 `(done=true)` 마크를 그대로 노출
   → 오늘 체크된 TODO가 0개였는데도 모델이 캘린더/노션 항목을 "오늘 한 일"로 서술

## 원칙 (사용자 지시)

- **"한 일"은 봇이 최종적으로 물어본 것 중 사용자가 직접 체크한 항목만** 인정
- 캘린더 항목이 일정인지 메모인지 **추측하지 않고**, 조금이라도 애매하면 텔레그램으로 물어봄
  (명사 단독뿐 아니라 상태 표시·디데이·재고 메모·타인 일정 등 전부)

## 변경 사항

### src/collectors/calendar.py
- "종료 시각 지남 = 완료" 추정 제거. `done` 필드 자체를 없앰

### src/main.py
- `_collect_uncompleted_tasks`: 캘린더 일정은 지났어도 **전부** 저녁 태스크 키보드 후보로 (체크해야만 한 일)
- 오늘 이미 체크한 항목(`todo_completed`)과 같은 텍스트는 키보드에서 제외
- 수집 직후 `split_ambiguous_calendar`로 캘린더를 확실한 일정 / 애매 항목으로 분리,
  애매 항목은 요약·키보드에서 빼고 4단계에서 항목별 질문 메시지 전송

### src/summarizer.py
- 시스템 프롬프트: "오늘 한 일 = '오늘 완료한 태스크' 섹션 항목만, 체크 안 한 것을 했다고 단정 금지
  (캘린더는 추정·기원 톤으로만)" 명시
- `_build_user_prompt`: `(done=true/false)` 마크 전부 제거. 노션/GitHub 섹션은 "참고용" 라벨
- `split_ambiguous_calendar` 추가: 인덱스 기반 LLM 분류 (daily_todo 분류기와 같은 패턴, llm.py 경유).
  "확실한 일정/할일" 번호만 고르고 나머지는 애매 처리. LLM 실패 시 전부 일정으로 폴백(기존 동작)

### src/telegram_bot.py
- `send_ambiguous_item_question`: `캘린더에 「item」가 있던데, 이건 뭐였어?` +
  [✅ 할일이었고 했어] [☐ 할일인데 못했어] [📝 그냥 메모야] 버튼.
  콜백 `a:{pid}:{done|todo|memo}`. **본문의 「」 형식을 바꾸면 webhook 파싱도 같이 바꿔야 함**

### api/webhook.py
- `_handle_ambiguous` 추가: 메시지 본문 「…」에서 항목 파싱 →
  done이면 tasks 컬럼에 체크 상태로 추가(한 일), todo면 미체크 추가(이후 defer 흐름 합류), memo면 기록 안 함
